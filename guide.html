1. Run locally

Requirements: Python 3.11+, Node.js 18+, MySQL 8 (or XAMPP/WAMP).

Database

CREATE DATABASE evoting CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

Backend

cd backend
python -m venv .venv
source .venv/Scripts/activate      # Git Bash. macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
pip install cryptography
cp .env.example .env
python seed.py --demo              # demo voters DEMO/001 ... DEMO/005
uvicorn api_web.main:app --port 8001 --reload

Set this in backend/.env (root user, no password):

DATABASE_URL=mysql+pymysql://root:@localhost:3306/evoting
JWT_SECRET=a-long-random-string
ADMIN_PASSWORD=ChooseAStrongPassword
OTP_DEV_MODE=true                  # prints one-time codes in this console (testing only)

Web app (new terminal)

cd web
npm install
npm run dev

Voters: http://localhost:5173/   Admin: http://localhost:5173/admin/login

Voter flow: allow location, enter DEMO/001, choose email or SMS, then type the code shown in the API console ([DEV OTP] ...).

Voters cannot log in until the admin clicks Open voting in Settings.

2. Run with Docker

cp .env.example .env               # then edit passwords and JWT_SECRET
docker compose up -d --build
docker compose logs -f api_web     # shows one-time codes while OTP_DEV_MODE=true

Open http://localhost:8080/ (voters) or http://localhost:8080/admin/login (admin). Add --profile mobile to also start the mobile API.

docker compose down        # stop (data kept)
docker compose down -v     # stop and delete the database

3. Restore from evoting.sql

mysql -u root evoting < evoting.sql

Or use phpMyAdmin: select evoting, then Import, then choose evoting.sql. For Docker, put the file in the project root, uncomment the evoting.sql volume line in docker-compose.yml, then run docker compose down -v and docker compose up -d --build.

The dump may contain real voter data. It is listed in .gitignore, so it will not be pushed to GitHub.

4. Git global config and push to GitHub

One-time global configuration (per computer)

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git config --global core.autocrlf true      # Windows only
git config --global --list                  # verify

Create the repository on GitHub

On github.com choose New repository, name it (for example evoting), keep it Private, and do not add a README, .gitignore or licence (the project already has them).

Push all files

Run these in the project root, the folder that contains backend, web, mobile and README.md:

git init                       # skip if the folder is already a Git repo
git add .
git status                     # check: .env and evoting.sql must NOT be listed
git commit -m "Initial commit: SUG/SRC e-Voting System"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/evoting.git
git push -u origin main

If git remote add says the remote already exists, use git remote set-url origin https://github.com/YOUR-USERNAME/evoting.git.

GitHub does not accept account passwords for pushes. A browser sign-in window opens through Git Credential Manager, or use a personal access token (GitHub: Settings, Developer settings, Personal access tokens) as the password.
If .env or evoting.sql appears in git status, stop. Run git rm --cached .env (or the file name), confirm .gitignore is present, and commit again. A secret that was pushed must be treated as leaked: change the passwords and JWT_SECRET.

Later updates

git add .
git commit -m "Describe your change"
git push
